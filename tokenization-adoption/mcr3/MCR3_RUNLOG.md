## ROOT CAUSE FOUND — the "flaky node pool" was never flaky
During MCR-3 the ATOM leg failed twice with the same "unable to verify single signer
signature" error seen during ATOM-CERT-1. Root-caused this time (local verification gate
added before broadcast): the early hand-rolled builders (ATOM-CERT-1 attempts b4/b5 and
the first MCR-3 leg build) passed an ALREADY-HASHED digest to ecdsa's
`sign_deterministic`, which hashes its input again — producing a signature over
SHA-256(SHA-256(SignDoc)). Cosmos verifies against SHA-256(SignDoc). The nodes rejected
correctly every time. Fix: `sign_digest_deterministic` over the digest (single hash),
plus a mandatory local verify (verify_digest with this ecdsa version's argument order
`verify_digest(signature, digest)`) before any broadcast.
- This CORRECTS the ATOM-CERT-1 addendum's "mixed node versions" hypothesis: the publicnode
  pool behaved correctly; the defect was local (double-hash). Disclosed forward-only;
  the b1-b3 parse errors were separate, real encoding bugs (already disclosed).
